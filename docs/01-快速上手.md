# 01 快速上手

## 模型和规格

接口：`POST https://api.minimax.cn/v2/video_generation`（国际站是 `api.minimax.io`），返回 `task_id`；再 `GET /v2/query/video_generation/{task_id}` 轮询，成功后 `task.content.url` 就是成片地址，直接下载。官方建议约每 10 秒查一次。

| 模型 | 分辨率 | 时长 | 备注 |
|---|---|---|---|
| MiniMax-H3 | 768P、2K | 4–15 秒（整数） | 画质最好 |
| MiniMax-H3-Highspeed | 仅 768P | 4–15 秒 | |
| MiniMax-H3-Lite | 480P、768P | 4–15 秒 | 参考生成需指定具体画幅，不能 adaptive |
| MiniMax-H3-Max | 480P、768P | 5–15 秒 | |
| MiniMax-H3-Max-Turbo | 480P、768P | 实测 5–15 秒可用 | 最快最便宜；官方请求参考页没写它，价目表有它，实测能用 |

画幅 `ratio`：`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`adaptive`。文生视频必填且不能 adaptive；首尾帧模式由图片决定；参考模式可选。提示词最多 7000 字符。**时长、分辨率、画幅要写在请求字段里，写在提示词里无效。**

## 三种生成方式

| 方式 | 给什么 | 用在哪 |
|---|---|---|
| 文生视频 | 只有文字 | 没素材，从零想象 |
| 图生视频（首帧 / 尾帧 / 首尾帧） | 文字 + 1–2 张图 | 想指定开头或结尾；做长片时用上一条的末帧续拍 |
| 多模态参考 | 文字 + 参考图（≤9）、参考视频（≤3，每段 2–15 秒，合计 ≤15 秒）、参考音频（≤3，同上） | 锁人物、借动作、借运镜、借音色 |

两条限制：首尾帧模式不能和参考类素材同时用；音频不能单独当参考，要搭配图或视频（第三方教程的说法，官方文档写的是音频只能用在参考场景）。图片 ≤30MB，视频 ≤50MB，音频 ≤15MB，整个请求体 ≤64MB，大文件请用公网链接。本地图片脚本会自动转成 data URI。

## 用脚本跑

```bash
export MINIMAX_API_KEY="你的key"
python3 scripts/h3.py quota
python3 scripts/h3.py gen --prompt "……" --duration 5 --resolution 480P --ratio 9:16
python3 scripts/h3.py gen --prompt "只写会变化的部分" --first-frame last.jpg --duration 8
python3 scripts/h3.py gen --prompt "图1是主角，保持脸、发型、服装不变……" --ref-image me.png --duration 10 --ratio 9:16
```

默认模型是 Turbo，480P。换档位：`--model MiniMax-H3 --resolution 768P`。

## 额度和等待

- 周额度剩多少、几小时后重置：`python3 scripts/h3.py quota`（`weekly` 是剩余百分比，`weekly_reset_s` 是距重置的秒数）。
- 用量统计滞后约 20 秒，刚生成完立刻读会少算一条。
- 生成时间差别很大：Turbo 480P 15 秒的片子不到 11 秒；H3 768P 10 秒的要近 3 分钟。
- 失败或命中安全审核的任务按官方说明不扣额度（资源包文档里的说法）。

## 出错对照

| 状态码 | 意思 | 办法 |
|---|---|---|
| 401 | key 不对 | 检查环境变量，订阅 key 以 `sk-cp-` 开头 |
| 402 | 余额不足 | 周额度用完，等重置，或换更便宜的档位 |
| 422 | 命中敏感内容 | 改提示词，别写真人名、敏感画面 |
| 429 | 请求太快 | 隔几秒再提交，别同时提交一大批 |
| 400 | 参数错 | 对照上面的表：时长范围、分辨率、画幅、素材数量 |
